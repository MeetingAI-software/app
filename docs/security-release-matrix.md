# Säkerhetsmatris för samlad release

Denna matris gäller `origin/main` `603094d78fe0c8f01208f69636e955768fe27663` mot integrationskod `d237bdb` (G31/G37-fixen). Den är ett granskningsunderlag, inte ett påstående att produktionen är säker. Statusarna anger kodläget; faktisk aktivering, historisk data, migration och providerbeteende måste kontrolleras separat. Standard-skanning `50d5577f-c18d-4d07-a22b-90e9e597467c` gällde den tidigare kodcommitten `0c5adc9`, granskade 121/487 inventerade filrader fullständigt och återfann G12. Frånvaro i den skanningen stänger inget annat ID. Diffskanning `9ac53c39-3e9c-48b9-868c-0bdfc6201091` granskade 193/193 ändrade källfiler i `603094d..8d497a2`, rapporterade G12 och en ny risk vid blandad utrullning av migration 0022 samt sköt upp Google-klockskevhet och långvariga Paddle-anrop. Den är partiell som slutsats eftersom drift- och providerfakta saknas. En fullständig Standard-uppföljning av samtliga ursprungliga fynd återstår.

`Verifierat i kod` betyder att negativt och legitimt lokalt flöde finns för den angivna vägen. `Villkorligt skydd` betyder kodspärr med kvarvarande drift-/providerberoende. `Kvarstående` betyder angreppsvägen finns kvar. `Okänt` betyder att underlaget inte räcker. PR-nummer avser review-enheter i den staplade kedjan; ingen är mergad till main.

## Saknade releasebevis

- Effektiva Railway-flaggor, providerhemligheters närvaro, faktisk proxykedja, Vercels produktions-API-ursprung och vilka funktioner som är aktiva har inte kunnat läsas med tillgänglig åtkomst. Koddefault är inte driftbevis. G12 blockerar om `PUBLIC_REGISTRATION_ENABLED=true`; vid verifierat `false` kan den uttryckligen accepteras som rest-risk med funktionen fortsatt avstängd.
- Migration 0022 ändrar kvot-/unikhetsregler före API-deploy. Gamla repliker kan skapa möten utan nya reservationer efter backfillen. Kräver trafikspärr/dränering, datakontroll, stagingrepetition, backup och namngiven rollbackansvarig före merge. 0024 stoppar vid dubbla bot-ID:n; 0030 raderar terminala liverader.
- G31/G37-fixen i `d237bdb` behåller osäkra uppladdningsanspråk efter svep och retry exhaustion. Testad lokalt på Node 24, inklusive PGlite-sekvens med sent jobb-ID och 60 s avräkning. Den måste få Node 20-CI och ny slutlig uppföljningsskanning. Okända providerutfall kräver fortfarande operatörsavstämning.
- Historiska D01/D02/D03/D17-data samt Recall/AssemblyAI/Storage-prov enligt D24 kan inte bevisas av kod eller tester. Utan dessa prov ska berörda funktioner förbli avstängda eller ha ett uttryckligt dokumenterat releaseundantag.
